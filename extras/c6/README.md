# The ESP32-C6 firmware

`examples/InstallFirmware/c6_firmware.h` is generated by `make_c6_header.py` from an
ESP-Hosted co-processor image. The one shipped:

- **esp-hosted-mcu v2.12.13** (github.com/espressif/esp-hosted-mcu), its `slave/`
  project, `idf.py set-target esp32c6`, default configuration (SDIO transport,
  Bluetooth on), built with **ESP-IDF v5.5.5**.
- 1,227,008 bytes, SHA-256 `16b8fff0de8712b896d450da19ce8b027da7494c56b7fa891a8075d061fa51d7`.

That is the ESP-Hosted version the Arduino ESP32 core 3.3.12 builds its host side
against (and the IDF version the core itself was built with). It matches, in version,
IDF and size, the `esp32c6-v2.12.13.bin` Espressif publishes for the core's own
online updater; the two differ only in build path and date.

When a newer Arduino core moves to a newer ESP-Hosted, rebuild the same way at that
version and run `python3 make_c6_header.py path/to/network_adapter.bin`.

**ESP-Hosted 3.x is not used here.** A 3.x co-processor can't talk to a 2.x host,
which is what Arduino core 3.3 has, so it would stop Wi-Fi in every Arduino sketch.
ESP-IDF projects on ESP-Hosted 3.x hosts work with this 2.x firmware.
